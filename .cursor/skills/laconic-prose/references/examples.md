# Before and after

Each edit uses only facts in its supplied input. Missing evidence stays a gap.

## Keep the measurement

**Before:** 'Review time fell from 30 minutes to 8, significantly improving productivity.'

**After:** 'Review time fell from 30 minutes to 8.'

Both times survive. The wider productivity claim has no support in the input.

## Avoid invented specifics

**Before:** 'The integration improved efficiency.'

**Response:** The draft gives no measure or mechanism for the efficiency claim. Retain it with that gap identified, or ask for evidence when the requested result requires substantiation. Do not invent deploy times.

## Remove unsupported praise

**Before:** 'The detail that makes it work: a separate agent grades the output. This marks a pivotal moment for evaluation tooling.'

**After:** 'The tool works because a separate agent grades the output.'

The edit retains the supplied explanation without adding a claim about being first or removing the need for human review. The explanation itself remains the writer's claim.

## Preserve attribution when evidence is missing

**Before:** 'Studies show that shorter feedback cycles improve response times.'

**Response:** Identify the missing study. Do not invent a study date or response time measurements, and do not remove 'Studies show' to present the claim as established.

## Remove superficial analysis

**Before:** 'The launch adds file search, underscoring the team's commitment to better workflows.'

**After:** 'The launch adds file search.'

The input supplies no editor integration or supported file types to add.

## Preserve technical meaning

**Before:** 'We estimated robust standard errors and measured financial leverage. The service retries failed requests.'

**After:** unchanged.

The terms are precise and the service performs a literal action.

## Preserve scope and negation

**Before:** 'This should handle most malformed inputs, though I haven't tested Unicode edge cases. The fee is refundable, not transferable.'

**After:** unchanged.

The uncertainty, untested case and transfer exclusion all affect meaning.

## Preserve the voice

**Before:** 'I spent four days on this and honestly I'm still not sure it's right. The parser works. The error messages are garbage. I'll fix them when someone complains.'

**After:** unchanged.

The uncertainty, blunt assessment and short sentences belong to the writer.

## Remove unnecessary hyphens

**Before:** 'Our open-source parser is high-performance and well-tested, and it sends an e-mail when a long-term job fails. It's a best-in-class, future-proof solution.'

**After:** 'Our open source parser is fast and well tested, and it sends an email when a long-term job fails.'

'Open source' is a set phrase and 'email' is closed up. 'Well tested' follows its noun, so it loses the hyphen. 'Long-term job' keeps it before the noun. 'High-performance' becomes 'fast' only because the draft claims speed. The buzzword sentence carries no claim and goes. The edit adds no benchmark.

## Apply the requested locale

**Before:** 'The organization will analyze the color settings in the center panel.'

**After:** 'The organisation will analyse the colour settings in the centre panel.'

Change surrounding prose in context. Preserve exact quotations, code such as `color` and official titles such as 'World Health Organization'.
